# 意图规格：<名称>

> 逐题追问的收敛产物。目标：让「导师到底要什么」在动笔前就可证伪。
> 这是实现与验收的共同契约；填写时的唯一标准是「可证伪」——每一句都应当能回答「什么证据出现，我就知道它没做到」。

## 1. 背景与动机

- 谁、在什么场景下、遇到了什么问题？
- 为什么现在做？（五个为什么的结论链）

## 2. 目标（可证伪）

- 一句话意图快照：我们要做出「什么」，边界到「哪里」为止。
- 关键术语定义（避免同名不同义）。

## 3. 验收标准

> 格式：当 `<条件>` 时，用户能看到/发生 `<可观察结果>`，且 `<不该发生的事>` 不发生。

- [ ] 当 … 时，…，且 … 不发生
- [ ] 当 … 时，…，且 … 不发生

## 4. 非目标

- 明确不做的事（防止范围蔓延与「顺手加功能」）。

## 5. 约束与已定取舍

- 已知约束（时间/预算/兼容性/技术栈/合规）。
- 冲突与取舍记录：「X 与 Y 冲突，经用户拍板，牺牲 Y」。

## 6. 反例检验记录

- 它最可能以什么方式失败？发现者（谁/哪一轮诘问）？
- 对每个失败模式：可接受吗？兜底/回滚方案是什么？

## 7. 未决问题

- 留给后续轮次的问题清单（诘问未收敛的部分，禁止悄悄替用户决定）。

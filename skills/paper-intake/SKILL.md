# paper-intake：一次问到位

## 为什么需要它

AI 写论文最大的浪费不是写错，而是**写对了你不需要的东西**：按通用模板排了一版，结果你们学校要求页边距 3cm；
写了 1.8 万字，学校要求 1.2 万；参考文献排在文末，学校要脚注式；实验数据用的是模拟数据，导师要真实运行结果。
这些都是**一次追问就能消除的返工**，而不问的代价是整章重写。

追问助产术在这里的用法：**承认无知 → 下定义 → 反例检验 → 暴露矛盾 → 收敛留痕**。
规格文档就是"留痕"的产物。

## 铁律（缺一条就退化成烦人表单）

1. **一次只问一个问题**。工具每次只返回一个问题；模型不得把整张问卷一次性倒给用户。
2. **问题必须由人回答**。模型不得替用户猜测后直接开写；用户答"不知道"时给 `hint`（去哪找：教务处网站、学长模板、导师），而不是替他决定。
3. **便宜**。每个问题都要说清「为什么问」「影响哪个产出物」，让用户一眼判断值不值得答。
4. **有终止条件**。规格可证伪即停；`required` 项齐全即可进入写作，其余标为已知缺口，绝不无限追问。
5. **材料优先**。材料清单里已经能读出来的（如学校模板文件已存在），不再问，只请用户确认。
6. **绝不覆盖**。规格文档可以重渲染，但已回答的答案永不丢失。

## 标准流程

```
thesis_ingest            # 1. 先摄取材料：docx/xlsx/pptx/pdf/md/csv → 文本 + 材料清单
   ↓
thesis_intake start      # 2. 立规格会话（读取材料清单，跳过已能从材料回答的问题）
   ↓
thesis_intake ask        # 3. 取一个问题 → 原样转达给用户（不要改写、不要附答案）
   ↓
thesis_intake answer     # 4. 用户回答 → 记录 → 自动刷新《意图规格》→ 返回下一个问题
   ↓ （循环 3-4，直到 required 齐全）
thesis_intake done       # 5. 校验必答项；不齐则列出缺口并拒绝完成
   ↓
00-管理/意图规格.md       # 6. 唯一真相：后续写作/构建/检查/降重/PPT 都以它为准
```

## 追问覆盖域（问题库的骨架）

| 分节 | 典型问题 | 不答的代价 |
|---|---|---|
| 学校与规范 | 学校/学院/专业、学位类型、**学校模板文件拿到了吗** | 格式检查与 docx 排版全部失真 |
| 课题 | 题目、方向、导师给定还是自选 | 选题工作坊无法给出备选 |
| 字数 | 正文字数要求、各章分配 | 章节评审的字数区间失去意义 |
| 查重 | 查重系统、重复率阈值 | 降重没有目标线 |
| AI 政策 | 学校对 AI 使用的明文规定 | 合规策略无从谈起（这是红线，必须问） |
| 时间线 | 开题/中期/查重/答辩日期 | 排期与催办失效 |
| 技术栈与代码 | 技术栈、**已有代码位置** | 实现章节写成空谈，答辩素材无来源 |
| 数据 | 实验数据来源、**是否已有真实运行结果** | 零假数据红线无法保证 |
| 文献 | 数量要求、年限要求、引用格式（GB/T 7714？） | 文献综述与著录格式返工 |
| 答辩 | 形式、PPT 页数、时长、是否盲审 | 答辩材料方向错 |
| 图表公式 | 编号规范、图题表题位置 | 全文编号返工 |

## 与其它工具的配合

- `thesis_ingest` 的产物 `00-管理/材料清单.md` 是本技能的输入；清单里出现学校模板 → 不再重复问模板。
- 用户对某个技术方向拿不定主意时，转 `thesis_decide` 记录决定（内容/理由/备选），答辩时要用。
- 结论写回规格后，用 `fact_remember` 把**跨课题复用**的稳定事实（学校规范、导师偏好、你的写作风格偏好）存进跨会话事实，key 用 `thesis.<课题 slug>.<属性>` 或 `user.<属性>`。
- 规格确认后进入 `thesis-pipeline` 的阶段流程；闸门 G1/G3 的输入就是这份规格。

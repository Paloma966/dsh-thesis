# 答辩准备

**答辩的本质**：老师验证两件事——①系统是你做的（问实现细节）②你懂你的设计（问为什么）。
准备的核心不是背稿，而是**把决定日志与设计文档里的"为什么"讲顺**。

## 1. PPT 大纲（10-12 页，模板在 07-答辩/PPT大纲.md）

每页原则：**图多字少、一页一个观点、真实截图优先**。

| 页 | 内容 | 要点 |
|---|---|---|
| 1 | 封面 | 课题/学生/导师 |
| 2 | 目录 | 与讲述顺序一致 |
| 3 | 背景与意义 | 1 页讲清痛点，用图/数据 |
| 4 | 国内外现状 | 一图带过，落点是"现有不足 → 本课题" |
| 5 | 需求分析 | 功能点列表/用例图 |
| 6 | 系统总体设计 | 架构图（和论文图一致） |
| 7-9 | 关键实现 | 每页一个模块：截图/核心代码/设计取舍；**这是老师最细看的部分** |
| 10 | 测试 | 真实数据图 + 结论 |
| 11 | 总结与展望 | 已完成 + 不足（诚实） |
| 12 | 问答页 | "谢谢，请各位老师指正" |

## 2. 预答辩问题库（结合你的材料生成）

每类问题对应准备材料，逐一准备：

| 问题类型 | 示例 | 准备材料 |
|---|---|---|
| 实现细节 | "X 模块具体怎么实现的？" | 04-实现 代码 + 答辩演练记录 |
| 技术选型 | "为什么用 A 不用 B？" | 03-设计/技术选型论证.md + 决定日志 |
| 需求来源 | "这个需求怎么来的？" | 03-设计/需求分析.md |
| 工作量 | "哪些部分是你做的？" | git 提交记录 + 决定日志（诚实说明 AI 辅助，强调自己做的设计决策与验证） |
| 数据可信 | "测试数据怎么得到的？" | 05-实验测试/结果 + 复现步骤 |
| 不足 | "你觉得哪里没做好？" | 论文第 7 章不足与展望（提前准备 2-3 个诚实不足 + 改进方向） |
| 创新点 | "你的工作有什么亮点？" | 绪论"本文主要工作" + 对比实验 |

**答题心法**：先结论后展开；答不上来的诚实说"这里我考虑得不够，之后可以…"；不要辩解式回答。

## 3. 模拟问答演练流程

1. 运行 `thesis_defense`：提取《答辩素材》（章节概览/技术选型/关键决定/测试数据/git 工作量）并生成《预答辩问题库》骨架。
2. 依据《答辩素材》把问题库中的 <> 占位替换为系统实际名称，生成 15-20 个具体问题；每个问题都要能回答到证据锚点（如"选型理由见技术选型论证.md 第 2 行"）。
3. 用户口头回答 → 记录要点到 07-答辩/问答演练.md。
4. 对答不上来的问题：回到对应材料补学，把答案写进演练记录；**"你的系统怎么实现的"这类问题用 `defense_code_*` 走一遍代码演练**（技能 `code-walkthrough`），不要靠背答案。
5. 至少完整演练 2 轮；第 2 轮随机抽题。

## 4. 答辩前清单

- [ ] PPT 与论文数据、截图一致（零伪造）
- [ ] 系统在演示电脑上真实跑通（提前装环境、准备离线演示兜底）
- [ ] 常见问题 15 个以上有演练记录
- [ ] 决定日志通读一遍（"为什么这么做"全都有答案）
- [ ] 实现细节类问题过了代码演练（`defense_code_status` 显示自己系统讲得清）
- [ ] 诚实原则：AI 辅助了哪些、自己做了哪些，能清晰表述

## 幻灯产出链路（`thesis_slides`）

**Markdown 是唯一真相**：幻灯源文件是 `07-答辩/PPT.md`（Marp 兼容），`.pptx` 只是它的派生产物。
这样幻灯可以被 git diff、可以在答辩前一天晚上还敢改，也不依赖任何 Office 版本。

```
thesis_defense          → 07-答辩/答辩素材.md + 07-答辩/预答辩问题库.md
thesis_slides outline      → 07-答辩/PPT.md（10-12 页，每页含讲稿要点与证据锚点）
thesis_slides check        → 页数/要点数/字数/讲稿/锚点/时长 六项确定性检查
thesis_slides convert      → 探测 marp / npx marp-cli / pandoc；有则产出 07-答辩/PPT.pptx
                          没有则写 07-答辩/PPT转换说明.md（含可直接复制的命令与兜底方案）
thesis_slides guide        → 只输出转换指引，不执行
```

等价斜杠命令：`/thesis-defense prepare [页数] [undergrad|master] [force]`、`convert`、`check`、`guide`。

硬约束（`check` 会逐条查）：每页要点 3-6 条、单条 ≤ 30 字、每页必须有讲稿与证据锚点、
不得出现"待补充/TODO"、预计时长 8-12 分钟（每页 40-60 秒）。

**证据锚点为什么是硬要求**：老师问"这个数据哪来的"时，你必须能在 3 秒内点到具体文件
（`05-实验测试/结果/xxx.csv`、`06-论文/章节/06-系统测试.md`），而不是说"我记不清了"。

**无 marp/pandoc 时怎么办**（离线常见）：`thesis_slides convert` 会给出三条路——
① `npx --yes @marp-team/marp-cli PPT.md --pptx`（有网即可，免安装）；
② pandoc（`pandoc PPT.md -o PPT.pptx`）；③ 把 `PPT.md` 粘到 marp 网页版或用 WPS/PPT 手工成稿（幻灯文字已是最终稿，成稿只是排版）。
